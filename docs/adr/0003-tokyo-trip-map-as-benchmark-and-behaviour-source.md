# tokyo-trip-map is the benchmark and the behaviour source; the flagship is generated from it

`tokyo-trip-map` is the hand-built ancestor of this repository: its design docs were mined to write the Eternal Pose plugin spec. The 2026-08-27 golden-path spec made it a read-only benchmark and forbade copying any code from it. That rule was written for a black-box acceptance run, before the flagship-first direction (ADR-0001).

We decided:

- **Behaviour code may be extracted.** Controllers, map viewport logic, Google adapters, and their tests may be lifted from `tokyo-trip-map` and refactored into the packages. Its trip content (coordinates, Place IDs, times, reservations) may not enter this repository except as a read-only oracle for the parity report.
- **The flagship is `examples/tokyo`**, generated by Eternal Pose from the itinerary text already recorded in the golden-path spec, and kept permanently in the repository as the end-to-end target.
- **The default visual system is the benchmark's own** oak-and-washi token system, ported and tokenised. This is the author's own work, so the rule against copying a reference site's trade dress does not apply.
- **Starter equals flagship minus trip content.** A byte-equivalence test enforces that the two never drift.
- **Public places are real; private facts are replaced.** Coordinates and Place IDs for restaurants, stations, and sights come from running the Enrich flow against Google Places once; the results are committed and CI never re-queries. Lodging, reservations, and tickets are replaced with structurally identical fictitious data.
- **The itinerary text gains an explicit movement mode per leg** so route behaviour is exercised from the first baseline run.

## Considered options

- Keep the copy ban and improve the starter's re-implementation. Rejected: the starter is the worse copy of the same ideas.
- Move `tokyo-trip-map` into this repository wholesale. Rejected: it has its own deployment chain, and it would blur the line between generated and hand-built sites.
- Fully synthetic flagship content. Rejected: public places are public facts, and a synthetic city would not exercise the Enrich flow honestly.

## Consequences

- Supersedes the golden-path clause "no implementation behaviour is copied from `tokyo-trip-map`". The clauses forbidding fabricated facts and the use of pasted clock labels as schedule remain.
- The experience contract in `@laugh-tale-island/testing` ships its own small synthetic fixture so a site without Tokyo data can run it; CI additionally runs the same contract against `examples/tokyo`.
